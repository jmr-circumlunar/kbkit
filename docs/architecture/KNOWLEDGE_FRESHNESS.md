# 信息新鲜度与漂移处理

| 漂移类型 | 当前可验证行为 | 后续处理 |
|---|---|---|
| 本地 Markdown 与索引不同步 | 查询前比较路径、修改时间和大小。变化项重新读入并计算哈希。手动 `index` 和定时 `task run` 核验全部文件哈希，捕捉保留时间戳且大小不变的编辑。 | 查询快路径仍需遍历文件元数据。建立万级库端到端 P95 基线，达到瓶颈后再引入变更队列或文件监听。保留周期哈希核验。 |
| 外部事实与生成页不同步 | `kb-ingest` 约定来源和哈希。现有维护任务没有持久化的来源订阅、游标推进或重新生成服务。 | 为授权代码仓库、文件和会话分别记录来源标识、当前版本、提取版本、关联页面、上次检查和上次成功时间。 |
| 复核到期和事实冲突 | `review_by` 过期会产生 lint finding 和持久化提案。检索尚未按有效性或生命周期筛除结果。 | 分别记录 `review_due`、`stale`、`contested` 和 `unverified`，将状态交给检索调用方。已经确认失效的生成页从默认结果退出，冲突保留双方证据。 |
| 调度漏跑或失败 | `maintain` 写 TaskRun 和运行报告。当前没有对漏跑窗口或来源刷新时限的检测。 | 使用宿主唤起任务，按每个来源的上次成功时间判断超期。重试从上次完整成功的游标继续，单个来源失败时报告其影响范围。 |

本地索引以查询发现外部编辑为第一道检查，以定时哈希核验补漏。`mtime` 和文件大小是快路径的筛选条件。索引更新失败时查询向调用方返回错误。一个库的维护与查询索引同步共用锁，第三方编辑器仍可在扫描期间改动文件。

外部来源的更新时限应按内容类别设置。代码类知识追踪已授权的分支或提交，按路径或符号定位受影响的知识页。普通文件按内容哈希识别差异。会话只消费授权摘要并保留处理游标。定时任务在授权范围内更新符合条件的生成页，运行记录保留版本和差异。来源访问失败、工作区存在本地改动、源版本尚未同步时应在报告中标明。结论冲突和人工改过的生成页进入异常队列。

每次刷新先记录观察到的版本，再处理差异。关联页面写入并完成验证后，才推进来源的成功游标。页面仍引用已知旧版本时标记 `stale`。来源不可访问时保留最后证据和时间，标记 `unverified`。人工修改过的生成页保留现有内容，由 Agent 解释差异。代码来源允许读取指定远端分支的版本，更新知识页无需合并或切换用户的代码工作区。交互查询引用关键代码结论前，可对该结论涉及的来源进行按需核验。

用上次成功时间监控调度。首次启用时由用户选定频率，状态入口按该频率计算下次预期刷新时间和宽限期。若宿主停止唤起任务，下次查询或打开状态时仍要显示超期。用户通过宿主修改频率或暂停任务，刷新策略随之调整。

验收需要覆盖来源改变、来源暂不可达、任务漏跑、失败后重试、旧生成页退出默认检索，以及同一来源在重复运行时只更新同一页。性能比较应分别量首次全量构建、无变化查询、单文件变化后的首次查询和来源批量更新。现有唯一词查询耗时是旧查询路径的样本。
