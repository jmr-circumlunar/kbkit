# 代码类知识库的内容边界

代码仓库和知识库承担不同职责。代码仓库保存可执行源文件、完整配置、提交历史和构建产物，知识库保存帮助 Agent 理解和导航代码的派生事实。知识库页面必须能够回链到仓库、提交和文件位置，代码仓库始终是代码事实的权威来源。

## 可以进入知识库的内容

- 项目用途、边界、模块职责和目录结构；
- 对外 API、命令、配置项、环境要求和部署步骤；
- ADR、设计决策、约束、已知限制和迁移说明；
- 测试、CI、发布状态和失败摘要；
- 依赖、许可证、版本兼容性和安全修复摘要；
- commit、PR 或 issue 的变更摘要及影响范围；
- 从代码静态分析得到的入口、调用关系和数据流概览；
- 与用户工作相关的操作手册、排障步骤和经验结论。

## 不应进入知识库的内容

- 完整源代码、二进制、构建目录和大段生成日志；
- 密钥、令牌、个人隐私和未经授权的会话原文；
- 没有仓库路径、commit 或测试证据的代码断言；
- 将代码摘要当成代码本身的复制品。

## 生成页约定

命令 `knowledge bind-code` 绑定本地仓库、ref 和授权路径。日常维护自动更新 `_generated/code/<source-id>.md`。页面保留提交、文件路径和可验证符号，运行报告记录当前提交、更新前后哈希、事务号和异常。人工编辑过的生成页转为冲突。

架构结论、迁移说明、部署手册等由 Agent 核对代码与测试后维护，并登记对实现索引的依赖。依赖更新后，未复核的结论退出默认检索。完整流程见 [知识治理使用指南](KNOWLEDGE_FRESHNESS.md)。
