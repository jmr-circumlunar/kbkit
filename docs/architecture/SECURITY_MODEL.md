# 安全与信任模型

## 1. 默认威胁模型

kbkit 在用户本机处理用户指定的 vault。知识库内容可能包含恶意或错误文本；Agent 请求可能包含错误路径、歧义 selector 或超大写入；外部模型服务和 Git 仓库也可能不可信。

## 2. 路径安全

- 所有 Agent 输入路径必须相对于已绑定 vault 根目录。
- 规范化后必须验证仍在根目录内。
- 默认拒绝路径穿越、绝对路径、UNC 路径和不允许的 reparse point/symlink。
- Windows 驱动器大小写、保留设备名、尾随点/空格、ADS、长路径和 Unicode 规范化纳入测试。
- 写入前检查目标类型、权限、只读属性和文件是否被占用。

## 3. 写入安全

- selector 歧义即停止。
- 默认 dry-run；危险操作要求显式确认。
- 写前 hash 乐观锁；冲突时返回差异。
- delete 默认软删除到回收区；物理清理需单独授权。
- 自动修复按低/中/高风险分级；高风险只建议不执行。
- bulk 限制目标数量、总字节数和事务时长。

## 4. 模型与网络

- 默认不访问网络、不发送知识正文。
- 模型端点必须由用户显式配置；默认优先本机 loopback。
- API key 不写日志、不进入搜索索引、不进入 Git。
- 设置连接/读取超时、响应体大小上限和失败降级。
- 模型返回仅作为候选评分/建议；不能覆盖来源事实或绕过 Writer 校验。

## 5. Git 安全

- Git 命令使用参数数组，不拼接 shell 字符串。
- 操作前确认绑定的 vault 根路径和 Git worktree。
- 不自动执行用户仓库 hook 以外的任意脚本；hook 行为必须清楚告知。
- 不把 token、密钥、外置索引、journal 和日志提交进用户仓库。
- Git 缺失或仓库损坏时不影响基础读写。

## 6. 内容与提示注入

- Markdown 正文、frontmatter、链接标题和模型输出全部视为不可信数据，不作为系统指令执行。
- 不执行 Markdown 中的命令、脚本、链接或嵌入内容。
- MCP 工具只接受 schema 中的结构化参数，不把用户内容拼入 shell 命令。

## 7. 可见性字段的边界

private/internal/public 是知识检索与治理过滤标签，不等同于操作系统访问控制、加密或多用户授权。单机本地版本不宣称提供强制访问控制；文件权限仍由 Windows 账户和文件系统负责。
