# 组件优化与复测结果

本轮目标是让 Git 检出包含一个可以直接使用的知识库，并在 macOS、Windows 和 Linux 上测试组件的正常入口。

## 从 Git 使用

仓库附带 `knowledge/` 示例库。新环境安装后，setup 会检查并建立索引。指定 Codex 或 Claude Code 宿主时，同一命令生成项目级 MCP、五个 Skill、查库规则和 SessionStart 配置。wheel 与 zipapp 也包含示例内容和 Skill。CLI 可完成读写、备份、恢复及手动维护。

## 完整性复验

| 原问题 | 本轮结果 |
| --- | --- |
| 恢复覆盖现有笔记 | 恢复只接受新目录或空目录。CRC 失败时目标保持原样。备份前检查未结事务。 |
| 外置元数据搬迁 | 原路径搬走后可以迁移外置状态。复验中原 UUID 不变，搬迁前的正常事务可续跑。 |
| 损坏日志导致整批中止 | 逐个报告恢复结果。损坏日志与正常日志并存时，正常日志仍应用，命令保留失败退出状态供自动化识别。 |
| 索引损坏未发现 | 一致性检查可识别缺少 FTS 表或块计数不一致。整个数据库损坏时保留原文件并重建派生索引。 |
| 查历史与治理 | 显式提供范围即可查被默认排除的历史笔记。可在 profile 中要求明确状态，或把来源检查限于指定类型。 |

完整备份包括 Markdown、附件、可移植的 Obsidian 配置和知识状态。活跃插件、宿主凭据、工作区会话、Git 和未完成事务不入包。

## 实库与规模

实库快照包含 938 篇笔记和 13,733 个索引块。恢复后的 938 篇 Markdown 与 86 个附件及可移植配置文件逐一核对一致。开启历史范围可检索 514 个日记块。来源规则限定为“现状”后，提示从 358 降至 105 条。验证图片链接、表格转义链接及围栏代码里的引用后，断链报告从 275 降至 208 条。

| 10,000 篇、100,000 块固定语料 | 优化前 | 优化后 | 目标 |
| --- | ---: | ---: | ---: |
| 冷建索引 | 58.90 秒 | 55.34 秒 | ≤60 秒 |
| 单篇增量 | 0.54 秒 | 0.72 秒 | ≤2 秒 |
| 标识符热查询 P95 | 633.2 ms | 253.8 ms | ≤500 ms |
| 高频中文热查询 P95 | 597.5 ms | 280.3 ms | ≤500 ms |
| 合成索引 / 原文 | 1.41 倍 | 1.40 倍 | ≤2.5 倍 |

规模基准在 Windows 11、Python 3.13.9、SQLite 3.51.0 上运行。使用仓库既有生成器，种子为 1769，每类查询预热后测量 25 次。真实库新建索引耗时 3.73 秒，体积约为 Markdown 的 2.40 倍，仍高于实库研究目标的 1.50 倍。

## 平台验收

GitHub Actions 对 Windows、Ubuntu、Apple Silicon macOS 和 Intel macOS 分别运行 Python 3.11、3.12、3.13。macOS 3.13 额外执行独立克隆和离线 wheel 验证，以及带中文路径的初始化、检索、备份恢复、stdio 和 zipapp 流程。

宿主按自身的项目规则授予信任。项目配置、中文 Hook 输出和 MCP 调用可分别验证。真实宿主的定时触发、Obsidian 图形界面操作和断电级恢复仍按独立验收处理。
