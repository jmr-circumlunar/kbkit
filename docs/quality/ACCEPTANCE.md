# 独立性与发布验收

## 1. 原始 I1–I7 判据

| ID | 原始要求 | 建议验收 |
|---|---|---|
| I1 | 不依赖任何宿主软件 | 干净 Windows 环境不安装 Obsidian、插件或特定 MCP 宿主，CLI/Python 核心流程可运行 |
| I2 | 不依赖网络 | 断网完成 init→index→search→read→write→lint；Git commit 仅要求本地 Git |
| I3 | 零第三方依赖 | 核心运行时依赖清单为空；构建工具与可选适配器单独报告，不混淆 |
| I4 | 数据可搬运 | 复制 vault 到新路径，重建索引后同查询结果和内容 hash 一致 |
| I5 | 格式通用 | 普通 Markdown/frontmatter 可由第三方编辑器打开；未知语法不被破坏 |
| I6 | 分发即用 | pip 与 zipapp 各自通过干净环境安装/运行测试 |
| I7 | Agent 能力完整 | 通过统一 API/MCP 完成读、写、检索、图谱、巡检和版本操作 |

## 2. 原始文档中的 I8 缺口

原始总述在 M8 写“自动跑 I1–I8”，但只定义 I1–I7。本项目不擅自补造原始 I8。E1 必须确认：
- I8 是否遗漏；
- 若有，名称、目标、测试和失败等级是什么；
- 若无，将 M8 改为 I1–I7。

## 3. 发布门禁

P0：
- 无数据丢失、静默覆盖、路径越界和密钥泄露。
- TXN-01 至 TXN-07 全部通过或按定义进入可恢复人工冲突状态。
- 核心离线流程通过。
- Windows 干净环境安装与测试通过。
- 默认检索不泄露排除区内容。
- Frontmatter/Markdown 写回通过字节保留测试。
- 依赖检查符合冻结策略。

P1：
- Golden set 达到冻结阈值。
- 性能达到发布门槛。
- Git、MCP、zipapp 和任务调度通过各自适配器测试。
- 备份/恢复与跨路径搬运通过。

## 4. 验收报告必须包含

- 版本号、commit SHA、OS/Python/SQLite 环境；
- 测试用例总数、通过/失败/跳过；
- P0/P1 未通过项；
- Golden 指标和性能分位数；
- 故障注入恢复记录；
- 已知限制、平台限制和人工验收项；
- 是否满足 I1–I7（及最终确认的 I8）。
