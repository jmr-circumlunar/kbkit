# 产品范围、边界与非目标

## 1. 产品定位

kbkit 是面向 AI Agent 的本地 Markdown 知识库基础设施组件套件。它为一组普通 Markdown 文件提供可重建的块级检索、读取、写入、图谱、治理、版本与自动化能力。

一句话目标：让 Agent 能定位、引用和安全维护知识库中的具体内容块，而不必把整篇文档搬进上下文。

## 2. 目标用户与使用方式

- 主要消费者：AI Agent，通过统一 API、CLI 或 MCP 调用知识库能力。
- 人类维护者：通过 Obsidian、VS Code、Typora 或其他第三方编辑器查看和手工编辑同一批 Markdown 文件。
- 集成开发者：通过 Python API、CLI、MCP 或脚本将 kbkit 接入自己的 Agent 工作流。

## 3. 核心价值

1. 检索单元下沉到块，而不只是文件标题或摘要。
2. 命中后回源读取原文，索引不复制正文作为第二真相源。
3. Agent 读写走同一套结构化接口，避免不同入口各自实现业务规则。
4. 写入具备预检、冲突检测、差异预览、恢复和审计。
5. 知识具备来源、责任人、状态、复核日期和可信度等治理信息。
6. 检索质量和运行可靠性可通过测试集、基准和故障注入验证。

## 4. 第一版范围（提案）

- 本地知识库发现、注册、初始化和体检。
- Markdown、Frontmatter、标题、块、wikilink、embed、callout、tag 的受控解析。
- SQLite FTS5 块级索引、增量同步、状态检查和重建。
- 搜索、读取、目录树、文件清单、定位、分面、上下文预算打包。
- 双链图谱和缺链/孤儿页分析。
- 结构化写入操作、dry-run、差异、冲突检测、事务日志和恢复。
- 生命周期、来源、责任人、复核、可见性元数据。
- lint、提案箱、风险分级和可控自动化。
- 可选 Git 集成；无 Git 时基本知识库功能仍可用。
- CLI、Python API；MCP 作为 Agent 接口，首发传输方式待 ADR 冻结。
- 可选 OpenAI 兼容 HTTP 模型服务用于重排/相关性裁剪。
- pip 包与 zipapp 的可行性验证。

## 5. 明确不做

- 不提供 Web Viewer、Web UI、浏览器预览、Markdown 渲染或编辑器。
- 不替代 Obsidian、VS Code、Typora 等编辑器。
- 不提供云端知识库 SaaS、账号体系、远程同步或多租户服务。
- 不强制使用向量数据库、Embedding 服务或在线模型。
- 不内置模型权重、模型 SDK 或云端模型账号。
- 不把全文复制到索引作为正文真相源。
- 不把 Git 作为日常读写的强制前提。
- 不在没有确认的情况下自动执行高风险知识改写、合并或删除。
- 不承诺多个第三方编辑器在写事务期间观察到文件系统级的全局原子快照；这需要单独定义与验证。

## 6. 运行边界（提案）

- 第一开发与验收环境：Windows 本机。
- 第一版产品重点：单机、本地磁盘、单用户工作流。
- 网络共享盘、同步盘、多用户并发、远程文件系统暂不作为首发保证范围。
- Linux/macOS 是否列为正式支持平台，在平台 ADR 中确认；CI 可先做兼容性烟测。
- Git、模型服务和计划任务属于可选能力；核心检索和基础读写不能依赖它们。

## 7. 成功标准

成功不是“模块数量齐全”，而是：
- I1–I7 独立性判据有自动化验收；
- 初始化、索引、检索、读写、治理和版本路径端到端可运行；
- 事务故障注入后可恢复且不静默覆盖外部修改；
- golden set 能防止检索回归；
- 新用户可在干净 Windows 环境按文档完成安装和验收；
- 第三方编辑器打开的仍是普通 Markdown 文件。
