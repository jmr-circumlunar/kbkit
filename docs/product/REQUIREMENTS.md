# 产品需求清单

状态：V0.1 规划基线。需求编号用于关联模块、测试和里程碑；具体验收阈值以测试计划和 ADR 冻结结果为准。

## 功能需求

| ID | 需求 | 关键验收 |
|---|---|---|
| FR-001 | 知识库发现、注册、切换与初始化 | 能识别空目录和已有库；不擅自覆盖现有内容 |
| FR-002 | 初始化八步向导 | 路径、方向、范式、领域、字段、运行时区、Git/自动化、体检均有预览与确认 |
| FR-003 | Markdown 解析与原样保留 | 支持约定语法；未知语法不丢失、不被静默改写 |
| FR-004 | 块切分与稳定定位 | 标题、段落、列表、表格、代码块等可定位；身份与当前位置分离 |
| FR-005 | 本地全文索引 | SQLite FTS5；索引可删除重建；正文仍以 Markdown 为准 |
| FR-006 | 增量索引同步 | 新建、修改、删除、移动、重命名均可检测；可识别 stale |
| FR-007 | 块级检索 | 关键词、标识符、标题、字段过滤、状态过滤和可解释排序 |
| FR-008 | 上下文预算打包 | 结果包含来源定位；按 token/字符预算去重、截断和排序 |
| FR-009 | 图谱与导航 | wikilink、反链、缺链、孤儿页、标题树和目录清单 |
| FR-010 | 结构化写入 | create/set_prop/append/edit/move/rename/delete/bulk，默认 dry-run |
| FR-011 | 写入事务与恢复 | 写前校验、冲突检测、日志先行、崩溃恢复、divergent 保护 |
| FR-012 | 来源与生命周期 | source/owner/review_by/state/confidence/visibility 等字段可校验和过滤 |
| FR-013 | 治理与 lint | 12 条规则、风险分级、提案箱、可控修复 |
| FR-014 | Git 版本能力 | init/bind/status/commit/snapshot/log；Git 不可用时核心功能仍可用 |
| FR-015 | 自动化维护 | 定时巡检、增量索引、报告、任务去重、失败可见 |
| FR-016 | 多入口一致性 | CLI、Python API、MCP 共用应用服务与数据契约 |
| FR-017 | 可选模型辅助 | 通过 HTTP 调用户自备服务；失败显式降级到 L0 |
| FR-018 | 安装与分发 | pip 安装和 zipapp 均有独立验收；不以“文件生成成功”代替可运行验收 |

## 非功能需求

| ID | 需求 | 验收原则 |
|---|---|---|
| NFR-001 | 核心零第三方运行时依赖 | 干净环境检查运行时依赖；构建依赖单独披露 |
| NFR-002 | 离线可用 | 无网络完成核心流程；模型功能不配置时不访问网络 |
| NFR-003 | 数据真相唯一 | Markdown 是正文真相；索引、缓存、快照不成为第二真相 |
| NFR-004 | 数据可搬运 | 复制库目录后可重建索引，结果可复现 |
| NFR-005 | 写入安全 | 歧义停止、冲突拒绝、可恢复、不静默覆盖 |
| NFR-006 | 兼容第三方编辑器 | 不要求插件或专有 API，直接处理普通文件 |
| NFR-007 | 可观测 | 错误结构化，stale/index_dirty/事务状态显式 |
| NFR-008 | 隐私 | 默认本地处理；未经配置不把正文发送给模型或网络 |
| NFR-009 | 可测试 | 每个 FR/NFR 关联至少一个测试 ID |
| NFR-010 | 可演进 | 公开接口、持久格式和依赖例外通过 ADR 管理 |
